ANCILLARY PRICING PRODUCTION LAB

Testing, safely rolling out and monitoring ML pricing

Extra baggage and extra-legroom seats  |  Current Pricing vs New Model  |  Business Rules keep final control

Most airlines already price ancillaries in-house. The job is not to build a model that prints a price. It is to test a New Model against Current Pricing, keep Business Rules in control, roll out in traffic steps, and HOLD or Return to Current Pricing when the model is not healthy.

Current Pricing

Simulated existing system using route, days to departure, product, channel, and remaining inventory.

New Model

P(buy | price, booking context), then Price × P(buy) on an allowed grid. Trained on Databricks Free and Google Cloud (Colab + BigQuery); scored in the lab from an exported artifact.

Business Rules always finish the job (included-in-fare, loyalty, min/max, inventory, airport vs online bags, temporary RM caps). Example: recommend USD 175, cap USD 150, customer sees USD 150.

Products, rollout, checkout

v1 products: extra baggage and preferred / extra-legroom seat. Fare-brand upgrades are future expansion, not built here.

Rollout: Offline → shadow (log New Model, customer still gets Current Pricing) → 5% → 20% → 50% → 100%. Pause or Return to Current Pricing at any time.

Checkout fallback: New Model → Current Pricing → simple rules → a safe fixed price. If the model fails at checkout, the customer still gets a valid price.

How to read the four screens

1. Price ExplanationWhy this booking’s extra-legroom price moved versus Current Pricing. Both prices in USD.
2. Pricing ControlsTraffic percent, price bands, temporary caps. Not per-passenger approval.
3. Pricing Test ResultsRevenue per passenger, conversion, average quoted price. Simulated comparison.
4. Production MonitorCommercial, model, system, and rules health, then a Rollout Decision: HOLD / expand / return.

Resume bullets

Built a production lab that tests a New Model against Current Pricing for extra baggage and extra-legroom seats, then applies Business Rules so Revenue Management keeps final control.

Trained P(buy | price, booking context) on Databricks and Google Cloud (Colab + BigQuery), selected price by expected revenue, and compared Current vs New on simulated offer logs (synthetic + public data).

Added rollout (shadow to 5% to 20%), checkout fallback, and a monitor with a HOLD / Return to Current Pricing decision so a model is not left live when behaviour drifts.

Independent portfolio prototype. Results are simulated using synthetic and public data. This lab is not affiliated with any carrier and does not use airline internal data, systems, or proprietary pricing logic.
